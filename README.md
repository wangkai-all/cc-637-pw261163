# Merkle 快照差异工具

两份按业务主键保存的数据快照，即使只改了几行，也能借助持久化 Merkle 树快速定位
新增 / 删除 / 修改，而不必每次全表互比。纯 Python 标准库实现（无第三方依赖），
带一个零构建的网页界面。

## 启动

```bash
python3 -m merkle.app --data ./data --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

## 测试

```bash
python3 -I tests/test_merkle.py        # 33 个用例，约 3 秒
```

## 目录结构

```
merkle/
  canonical.py   确定性类型编码与哈希规则
  store.py       节点信封 / 行块 / journal / manifest 的持久化与自校验
  builder.py     分桶建树、重复主键拒绝、断点续建、原子发布
  differ.py      Merkle 剪枝差异、实测 IO 计数、逐行全量校验
  check.py       全量完整性校验与故障注入（演示用）
  sync.py        增量同步包：基线根守卫、暂存重建、目标根核对
  server.py      HTTP API + 静态文件
  sample_data.py 内置示例数据集
web/             单页前端（原生 HTML/CSS/JS，无框架）
tests/           端到端测试
```

## 关键设计

### 1. 确定性散列输入（`canonical.py`）

每个标量编码为 `类型标签:载荷字节长度:载荷`：

| 类型 | 标签 | 示例输入 | 编码 |
|---|---|---|---|
| 空值 | `N` | `null` | `N:0:` |
| 布尔 | `B` | `true` | `B:1:T` |
| 整数 | `I` | `100` | `I:3:100` |
| 小数 | `D` | `1.20` | `D:3:1.2` |
| 字符串 | `S` | `""` | `S:0:` |

- **空值 ≠ 空字符串**：`N:0:` 与 `S:0:` 哈希不同。
- **字段类型与长度都进哈希**：整数 `1`、字符串 `"1"`、小数 `1.0` 三者哈希互不相同；
  长度前缀让 `"ab"+"c"` 与 `"a"+"bc"` 不可能碰撞。
- **字段顺序固定**：按 schema 字段顺序编码，字段名本身也参与哈希，交换两列哈希即变。
- **小数规范化**：`1.20`、`1.2`、`1.200` 哈希相同；`100.00` 与 `100` 在 number 列相同，
  但 number 列与 integer 列仍按类型标签区分。
- **CSV 规则**：string 列的空单元格是空字符串 `""`；其它类型的空单元格是 `null`。

### 2. 固定主键区间，新增行不挤位（`store.py` / `builder.py`）

- 共 **256 个叶子桶**，桶号 = `sha256(主键编码)[0]`，与行数无关。
- 树形状恒定为 **256 叶子 → 16 个一级节点 → 1 根（共 273 个节点）**，空桶也有确定哈希。
- 新增一行只落入它自己的桶，其余 255 个桶的叶子哈希字节不变（有测试保证）。
- 桶内按主键编码排序，叶子信封保存 `(pk, row_hash)` 有序列表。

### 3. 持久化、剪枝与实测计数（`store.py` / `differ.py`）

- 每个节点是一个**信封 JSON**：载荷 + 自称哈希；加载时重算载荷哈希并比对，
  任何字节篡改都会在该节点被发现。
- 差异比较自顶向下：**子哈希相同则整棵子树跳过，连信封都不打开**；
  只有哈希不同的子树才继续下钻，直到叶子才读取行块。
- 页面上的读数全部是**实测值**，分两组呈现，绝不混用估算：
  - 树遍历：实际 `open` 的节点信封数、实际读取的行记录数、跳过 / 下钻的子树数；
  - 全量校验：从原始文件重新解析并逐行比较所读取的行数。
- 每次差异结果都附带一次独立的**逐行全量扫描**，断言 Merkle 剪枝答案与全表比较完全一致。

### 4. 重复主键拒绝（`builder.py`）

建树前先全量校验主键唯一性；发现重复立即抛错（HTTP 409 并列出重复键与行号），
不写任何节点、不存源文件、不发布 manifest。

### 5. 损坏定位，而非"整表都变了"（`check.py` / `differ.py`）

- `check_snapshot` 逐节点重算哈希、逐行重算 row_hash、并把树与原始源文件重新推导比对，
  报告**最小受影响范围**（通常精确到某个桶 `b3a`），而不是只看根摘要。
- 支持五种故障注入：叶子信封、行块单行、一级内部节点、根节点、原始源文件。
- diff 遍历对加载到的节点额外做**父子哈希链交叉校验**：信封自洽但与父节点记录的
  子哈希不一致时，按该子节点范围报损坏。

### 6. 断点续建与原子发布（`builder.py`）

- 每个节点写完并核对后向 append-only **journal** 追加 `DONE <node>`。
- 续建时只信任"journal 有记录 **且** 磁盘信封存在且校验通过"的节点，从下一个节点继续。
- 内部节点与根的子哈希一律**从已落盘的子信封重读**，杜绝内存陈旧状态。
- **根只有在全部 272 个子节点完成后才写入**；manifest 最后原子 `rename` 发布，
  未完成的快照在列表中标记为"未完成（可续建）"，永不参与 diff。
- schema 决策（字段顺序、类型、主键）在建树前写入 sidecar，保证续建推断零漂移，
  续建根与一次性构建的根逐字节相同。

### 7. 行级差异下载

`GET /api/diff/download?base=...&target=...` 下载包含全部新增 / 删除 / 修改行、
双侧行哈希、实测计数与逐行校验结论的 JSON 文件。

### 8. 增量同步包（`sync.py`）

- 同步包内含：**基线根哈希、schema 哈希、目标根哈希、目标行数、全部行级变更**，
  以及整包 SHA-256 自检和；每条变更带变更前后的行哈希。
- 接收端应用规则：
  1. 接收副本当前根或 schema 与包内基线不符 → **拒绝（HTTP 409），接收端数据不动**；
  2. 在私有暂存快照上应用增删改并重建 Merkle 树；
  3. 暂存根与包内目标根逐字节相等、行数一致才提升为正式快照，否则删除暂存区；
  4. 发布后再次核对目标根。
- 篡改包内任一字节 → 自检和失败；篡改行内容但保留旧校验和 → 行哈希校验失败。

## 内置示例覆盖的场景

页面点"载入示例数据 v1/v2"即可获得 `demo-v1` / `demo-v2`，其中刻意包含：

- 桶边界插入准备（`B-EDGE-00`，可在故障页定位其桶号）；
- 空值更正：`B-NULL-01` 的 `note` 从 `null` 改为 `""`（哈希必变）；
- 小数等价表示：`B-0007` 的 `7.70` 改为 `7.7`（哈希不变，不应出现在差异里）；
- 真实修改：`B-0010` 金额与备注同时变化；
- 新增一行 `B-NEW-500`（只有它所在的桶变化）；
- 删除最后一行 `B-LAST-99`；
- 构建到一半中断（构建页填入"第 N 个节点后中断"后续建）。
